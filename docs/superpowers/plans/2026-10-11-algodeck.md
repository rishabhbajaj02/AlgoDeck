# AlgoDeck implementation plan

> Execution: superpowers:executing-plans, inline in this workspace. Track verification in todos.md.

**Goal:** Build the working full-stack application defined in prompt.txt.
**Architecture:** Shared contracts, React/Vite, Express services and a Supabase repository. PostgreSQL functions provide atomic session creation, rating and import. Caller JWTs preserve RLS.
**Tech stack:** TypeScript, React, Supabase, Express, Zod, Pino, Vitest, PGlite.
**Spec:** ../specs/2026-10-11-algodeck-design.md

## Global constraints

- Never expose privileged credentials or trust submitted user IDs.
- Never bypass yesterday's exclusion to meet a target.
- Canonical migrations live only in supabase/migrations.
- Preserve attempt history and implement idempotent writes.
- Do not claim live Supabase behavior verified without credentials.

## Review focus

- Concurrent generation returns one session with one selection set.
- Repeated rating yields one immutable attempt and one schedule update.
- A second user cannot read or mutate records through HTTP or SQL functions.
- Invalid imports insert nothing and report row numbers.
- UTC/local midnight, archived questions, empty pools and unopened solutions remain correct.
